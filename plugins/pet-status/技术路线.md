# pet-status · 技术路线

## 来源
按用户口述的"桌宠状态上报"需求设计：让外部知道宠物现在的状态，便于多宠协同/看板显示。本地没有参考项目源码，功能点为需求描述，未逐项核对。

## 隐私优先的白名单设计
这是本插件最重要的设计点。桌宠 config.json 里有 `api_key`（用户自己的大模型密钥）。插件如果 `dict` 全量读取再返回，一旦宿主把 reply 打日志或显示出来，密钥就泄露了。

做法：**白名单**，只取 6 个非敏感字段，敏感字段根本不进内存返回值。这比"读完再删 key"安全——后者可能在某些分支漏删。

## 数据来源
| 字段 | 来源 |
| --- | --- |
| character | pet-character/character.json 或 config.character |
| mood / energy | pet-emotion/emotion.json |
| theme / size / follow | config.json（白名单过滤后） |
| last_behavior_at | pet-companion/companion.json |

## 它能做什么 / 不能做什么
- ✅ 只读聚合状态、脱敏配置、输出状态意图
- ❌ 不返回 API Key（刻意）
- ❌ 不修改任何状态

## 宿主接入
`intent_payload.type=pet_status` → 宿主可以据此同步 UI 或多宠协议（对接桌宠的 L3 互通 `outbox.jsonl`）。

## 已知边界
- 状态是各插件最近一次写入的快照，不保证实时。
- 没装其他插件时仍能返回基础状态（角色默认 silver_wolf、心情 calm）。
