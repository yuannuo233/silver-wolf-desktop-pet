# pet-actions · 技术路线

## 来源
按用户口述的需求，参考桌面宠物常见的动作类型：待机呼吸、打瞌睡、玩魔方、吃火锅、伸懒腰、挥手等。这里取常见的 13 类，映射到银狼桌宠已有的 11 组帧动画（`assets/stand/frames.json`）+ 补充意图。

> 说明：动作清单来自用户描述的 dsh 桌宠功能，本地没有该项目源码，未逐项核对；凡是银狼现有帧动画没有的状态（如魔方、火锅），一律降级为纯意图，宿主不支持时只显示气泡台词。

## 映射关系
| dsh 功能 | 本插件 action | 银狼现有帧 |
| --- | --- | --- |
| 待机呼吸 | breathe / idle | `idle`（28 帧含眨眼） |
| 打瞌睡 | doze | `doze`（18 帧） |
| 玩魔方 | cube | 无对应帧 → 纯意图（宿主可扩展） |
| 吃火锅 | hotpot | 无对应帧 → 纯意图 |
| 伸懒腰 | stretch | `stretch`（18 帧） |
| 挥手 | wave | `wave`（12 帧） |
| 吃棒棒糖 | lollipop | `lollipop`（18 帧） |
| 敲键盘 | typing | `typing`（16 帧） |
| 玩掌机 | console | `console`（16 帧） |
| 左右转向 / 屏幕漫游 | turn / run_left / run_right | `turn` / `run_left` / `run_right`（各 9/18/18 帧） |

## 为什么要 intent_payload 这个字段
开发说明只定义了 `text`（气泡文字）。但桌宠动作需要结构化指令。做法：在 reply 里加一个自定义字段 `intent_payload`，不破坏协议（宿主忽略未知字段即可），宿主按需读取。这是"baby MCP"向真 MCP 演进时的自然扩展点——将来可以换成 `tools/call` 的参数 schema。

## 它能做什么 / 不能做什么
- ✅ 返回气泡台词、输出动作意图、按时长/循环参数构造 payload
- ❌ 不直接调用桌宠的 `set_anim_state()`（插件是独立进程，拿不到宿主对象）
- ❌ 不驻留、不定时触发（一问一答）

## 宿主需要做什么
1. 解析 reply 的 `intent_payload`。
2. `type=play_action` 时调用桌宠动画状态机切到 `action` 对应状态。
3. 播完恢复 idle（或按 `loop` 决定）。

## 已知边界
- cube / hotpot 在银狼现有素材里没有对应帧，宿主若不支持会只显示气泡台词——这是预期降级，不会报错。
- 时长只是建议值，实际播多久由宿主控制。
