# pet-actions 动作点播 · 适配文档

> 适配目标：银狼桌宠（Silver Wolf Desktop Pet）v0.6.20
> 插件版本：v1.0.0　|　编写日期：2026-11-24
> 对应文件：`plugin.json` / `main.py` / `README.md` / `技术路线.md` / 本文件

## 1. 适配目标与前置条件

按用户口述的桌面宠物"动作点播"需求（待机呼吸、打瞌睡、玩魔方、吃火锅、伸懒腰、挥手、跑动、转身等）做成意图层。**注意：这些功能点是需求描述，本地没有 dsh-pet 源码可逐项核对。**

前置条件：

- 宿主要读 `intent_payload` 并调动画函数；只读 `text` 的话就只有气泡，桌宠不会动。
- 目标角色包里要有对应帧状态。银狼 v0.6.20 的 `assets/stand/frames.json` 定义了 `idle` / `drag` / `run_right` / `run_left` / `turn` / `action` 等状态，`_load_anim()` 在 `pet.py:314` 读取。

## 2. 本插件的返回字段

hello（实测）：

```json
{"t":"reply","ok":true,"intents":["pet_action","动作","表演","play","animate"],
 "description":"动作点播（输出意图，需宿主驱动动画）",
 "actions":["breathe","console","cube","doze","hotpot","idle","lollipop","run_left","run_right","stretch","turn","typing","wave"]}
```

ask（实测，`action=wave`）：

```json
{
  "t": "reply", "ok": true, "text": "嗨！干嘛叫我？",
  "intent_payload": {"type": "play_action", "action": "wave", "duration_ms": 2500, "loop": false},
  "action": "wave", "action_name": "挥手"
}
```

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `text` | str | 气泡文字（宿主原生支持） |
| `intent_payload.type` | str | 固定 `play_action` |
| `intent_payload.action` | str | 13 种动作之一，见 hello 的 `actions` |
| `intent_payload.duration_ms` | int | 建议播放时长 |
| `intent_payload.loop` | bool | 是否循环（呼吸/待机为 true，一次性动作为 false） |
| `action` / `action_name` | str | 顶层冗余字段，方便调试 |

## 3. 宿主接入点与字段映射

| 插件字段 | 宿主函数（v0.6.20 真实位置） | 处理方式 |
| --- | --- | --- |
| `intent_payload.action` | `pet.py:527 play_action(state)` | 一次性动作调它，播完自动回 idle |
| `intent_payload.action` | `pet.py:452 set_anim_state(state)` | 循环状态（breathe/idle）调它持续播放 |
| `action` 为 `run_left`/`run_right` | `pet.py:464 _face_travel(dx,dy)` / `:502 _start_run(state)` | 跑动有转身过渡，建议复用现有逻辑而非硬切 |
| `text` | `pet.py:773 show_bubble(text)` | 同时显示气泡 |

**动作名映射表**（插件 action → 宿主 frames.json 状态）：

| 插件 action | 宿主现有状态 | 是否需要补帧 |
| --- | --- | --- |
| `idle` / `breathe` | `idle` | 否（呼吸可用 idle 循环代替） |
| `typing` / `console` | `typing` / `console` | 否（宿主已有活动检测） |
| `run_left` / `run_right` | `run_left` / `run_right` | 否 |
| `turn` | `turn` | 否 |
| `wave` / `stretch` / `doze` / `cube` / `hotpot` / `lollipop` | 无对应状态 | **是**，需在角色包里加帧，或回落到 `action` 状态 |

宿主侧接法（伪代码）：

```python
reply = plugins_engine.ask("pet-actions", intent, args)
if reply.get("ok"):
    pet.show_bubble(reply["text"])
    p = reply.get("intent_payload", {})
    if p.get("type") == "play_action":
        state = p["action"]
        if state in pet.anim_states:      # 宿主已有这个状态
            if p.get("loop"): pet.set_anim_state(state)
            else: pet.play_action(state)
        else:
            pet.play_action("action")     # 缺帧时回落，不报错
```

## 4. 状态文件与路径

无状态。每次调用只做动作名 → 文案/参数的映射，不写文件。

## 5. 接入步骤

1. 拷 `plugins/pet-actions/` 到桌宠 `plugins/`，重启启用（id=`pet-actions`）。
2. **关键**：在宿主插件引擎里加 `play_action` 分支（见第 3 节伪代码）；只显示 `text` 的话桌宠不会动。
3. 核对目标角色包的 `frames.json`，确认有哪些状态；没有的动作用 `action` 回落。
4. 问"挥个手"→ 应同时出现气泡和挥手动作。
5. 若想让新动作真能动，给角色包补帧并在 `frames.json` 注册状态——这是**素材工作**，插件层解决不了。

## 6. 验证方法

```bash
cd plugins/pet-actions
echo '{"t":"hello"}' | python main.py
echo '{"t":"ask","id":"1","intent":"pet_action","args":{"action":"wave"}}' | python main.py
echo '{"t":"ask","id":"2","intent":"pet_action","args":{"action":"breathe"}}' | python main.py
```

预期：hello 列出 13 个 action；ask 返回 `play_action` 意图，`loop` 对呼吸为 true、挥手为 false。宿主内验证需看桌宠是否真的播放对应帧。

## 7. 边界与降级

- **插件只输出意图，不直接操作窗口**；动画是否发生取决于宿主实现。这是协议边界，不是 bug。
- 动作名不在 13 种内时返回 `ok:false` + 提示，不会崩溃。
- 目标角色包缺帧时建议宿主回落到 `action` 状态并保留气泡，别让桌宠卡住。
- 本机源码有 `play_action()` / `set_anim_state()` 真实函数，但**没有** `plugins_engine.py`（插件加载器在 `F:\银狼\上传源码`），所以宿主调用链为协议设计，未在本机实测。
