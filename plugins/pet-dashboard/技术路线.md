# pet-dashboard · 技术路线

## 来源
按用户口述的"桌宠看板"需求设计——把工作内容聚合成可播报的摘要。这里做成**只读聚合器**，不写任何状态。本地没有参考项目源码，功能点为需求描述，未逐项核对。

## 为什么不直接调用其他插件
开发说明的插件是一问一答的独立进程，插件之间互相调用要再起子进程、传 JSON、处理超时，复杂且慢。改为**直接读它们落盘的状态文件**：
- reminder → SQLite（只读连接）
- pet-emotion → emotion.json
- pet-character → character.json

这样一次调用就能聚合完，不需要嵌套进程。

## 容错设计
任何一项读失败都跳过那一项，不影响整体播报：
- SQLite 文件不存在 → 待办为空
- JSON 损坏 → 用空字典
- 都没装 → 只剩时间播报，仍能正常工作

## 它能做什么 / 不能做什么
- ✅ 聚合展示、摘要文本、只读状态
- ❌ 不做 AI 总结（那是大模型的事）
- ❌ 不修改其他插件状态

## 关于天气参数
`args.weather=true` 时给出提示"请单独查 weather 插件"，而不是在本插件内联网查天气。原因：保持本插件零网络依赖，避免一次播报要等两次 HTTP。

## 已知边界
- 摘要里的待办只取前 3 条，避免气泡太长。
- 状态文件是瞬时快照，不保证和其他插件完全同步。
