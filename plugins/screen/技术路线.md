# screen · 技术路线

## 与原 MCP 工具的差异
原 `tools/screen.py` 直接 `import mss`，缺依赖就 `ImportError`。插件版改为**三级降级**：

1. `mss` + `Pillow`（最快，跨平台）
2. `Pillow.ImageGrab.grab()`（Windows/macOS 自带方案）
3. 都没有 → 返回 `ok:true` + `degraded:true` + 安装提示

为什么不让第 3 级返回 `ok:false`：开发说明说 `text` 会显示在气泡里。缺依赖是"功能未启用"不是"出错了"，用友好提示更合适，也符合原 MCP 包"绝不让整个工具包不可用"的设计原则。

## OCR 的降级链
```
截图成功 → tesseract 在 PATH? ─否→ 返回截图路径 + 安装指引
                    └是→ pytesseract 可用? ─否→ 返回截图路径 + 提示
                                    └是→ image_to_string → text
```

## 为什么默认存 APPDATA 而不是包内
同 reminder：绿色软件可能只读，APPDATA 永远可写。用户要换目录可传 `args.out_dir` 覆盖。

## 安全边界
- 截的是主屏（`monitors[1]`），不是所有屏幕拼接，避免异常宽图。
- 不上传、不外发，纯本地文件。
- 截图文件名带时间戳，不覆盖旧图。

## 已知边界
- 需要图形会话；在无桌面的服务器/SSH 会话里会失败（返回明确错误）。
- OCR 准确率依赖 Tesseract 和语言包；中文需 `chi_sim`。
- 返回的是静态图片路径，不是图像本身；宿主若有视觉模型可以拿路径去识别。
