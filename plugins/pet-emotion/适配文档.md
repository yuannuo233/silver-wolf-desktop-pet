# pet-emotion 情绪系统 · 适配文档

> 适配目标：银狼桌宠（Silver Wolf Desktop Pet）v0.6.20
> 插件版本：v1.0.0　|　编写日期：2026-11-24
> 对应文件：`plugin.json` / `main.py` / `README.md` / `技术路线.md` / 本文件

---

## 1. 适配目标与前置条件

六轴情绪（happy / angry / sad / jealous / clingy / tired）+ 情绪惯性 + 精力值。按用户口述的"桌宠情绪系统"需求做成的**轻量可解释版**：用显式数值和规则，不依赖小模型。

前置条件：

- 宿主把 `state` 或 `intent_payload` 里的 `mood` / `expression` 映射到表情帧或提示文字。
- 状态落盘在 `%APPDATA%`，跨调用保留；时间流逝会衰减（情绪惯性）。
- 这是意图层，不改 `config.py` 的配置结构，不写桌宠主配置。

## 2. 本插件的返回字段

hello（实测意图）：`["emotion","情绪","心情","mood", ...]`。

ask（实测）：

```json
{
  "t": "reply", "ok": true, "text": "她现在平静，精力 77/100",
  "state": {"axes":{"happy":5,"angry":5,"sad":5,"jealous":5,"clingy":5,"tired":5},
            "energy":77,"mood":"calm","last_event":"","updated_at":1795512190.87},
  "intent_payload": {"type":"emotion_query","mood":"calm","expression":"calm","energy":77}
}
```

event 写入时（实测结构）：

```json
{"t":"reply","ok":true,"text":"她现在有点开心了（happy 轴 42/100）",
 "state":{...},
 "intent_payload":{"type":"emotion","mood":"happy","axes":{...},"expression":"happy"}}
```

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `text` | str | 气泡文字 |
| `state.axes` | dict | 六轴数值 0~100 |
| `state.energy` | int | 精力 0~100 |
| `state.mood` | str | 主导情绪英文 id |
| `intent_payload.type` | str | `emotion`（事件后）/ `emotion_query`（查询时） |
| `intent_payload.expression` | str | 建议表情 id，等于 mood |

支持 `args`：`action`（`query` / `bump` / `decay` / `reset`）、`axis`、`delta`、`hours`。

## 3. 宿主接入点与字段映射

| 插件字段 | 宿主函数（v0.6.20 真实位置） | 处理方式 |
| --- | --- | --- |
| `intent_payload.expression` | `pet.py:452 set_anim_state(state)` | 若角色包有对应表情帧则切；否则只用气泡 |
| `text` | `pet.py:773 show_bubble(text)` | 直接传入 |
| `state` | 宿主可读 `emotion.json` | 看板/状态插件据此聚合 |

**没有专门的"表情帧"接口**：v0.6.20 的 `frames.json` 状态是 `idle` / `typing` / `console` / `run_*` / `turn` / `action`，**不是**六情绪。所以 `expression` 目前更适合做**文案/语气选择**，而不是直接切帧。宿主若要做表情，需要在角色包里补情绪帧并在 `frames.json` 注册。

建议宿主接法：

```python
r = plugins_engine.ask("pet-emotion", intent, args)
pet.show_bubble(r["text"])
p = r.get("intent_payload", {})
# expression 先当语气标签用；有情绪帧的角色包再映射到 set_anim_state
tone = p.get("expression")
```

## 4. 状态文件与路径

- 文件：`%APPDATA%\SilverWolfPet\plugins\pet-emotion\emotion.json`
- 回退路径：`~/.config/SilverWolfPet/plugins/pet-emotion/`
- 内容：`axes` 六轴、`energy`、`mood`、`last_event`、`updated_at`（Unix 秒）
- `decay()` 按距上次更新的小时数自然回落，所以"情绪惯性"是**时间驱动**的，不需要后台线程。

## 5. 接入步骤

1. 拷 `plugins/pet-emotion/` 到桌宠 `plugins/`，重启启用（id=`pet-emotion`）。
2. 宿主在 AI 对话后调一次 `bump`（按对话情绪给某轴加减值），让情绪随互动变化。
3. 宿主问"心情"时调 `query`，用返回的 `text` 显示气泡。
4. 想做表情联动：给角色包补情绪帧后，把 `expression` 映射到 `set_anim_state()`。
5. 用 `reset` 可清空状态，便于测试。

## 6. 验证方法

```bash
cd plugins/pet-emotion
echo '{"t":"hello"}' | python main.py
echo '{"t":"ask","id":"1","intent":"emotion","args":{}}' | python main.py
echo '{"t":"ask","id":"2","intent":"emotion","args":{"action":"bump","axis":"happy","delta":30}}' | python main.py
echo '{"t":"ask","id":"3","intent":"emotion","args":{"action":"query"}}' | python main.py
```

预期：bump 后 happy 轴上升、mood 可能变 happy；query 反映最新状态；每次输出一行 JSON。状态文件可在 `%APPDATA%\...\pet-emotion\emotion.json` 直接查看。

## 7. 边界与降级

- **六轴是简化模型**，不等于 dsh 的真实情绪系统（那套可能用小模型判断）。这里刻意做成显式数值，便于调试和解释。
- 情绪不会自己"想起来"变化——`decay` 只在被问到时按时间差计算。宿主想让表情随时间长变，就定期 `query` 一次。
- 状态文件损坏时 `_load()` 回落到默认值，不崩。
- 宿主加载器不在本机源码里，宿主调用链为协议设计，未在本机实测。
