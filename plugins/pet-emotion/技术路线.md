# pet-emotion · 技术路线

## 来源
按用户口述的情绪陪伴需求设计：六条情绪轴、情绪有惯性、精力影响表情（低精力眼皮耷拉）。这里是**轻量可解释版**——用显式数值和规则，不依赖小模型。本地没有参考项目源码，上述功能点为需求描述，未逐项核对。

## 情绪模型
```
axes = {happy, angry, sad, jealous, clingy, tired}  各 0~100
energy = 0~100
mood = 主导轴（<20 视为 calm）
```

**刺激（set）**：目标轴 += strength（上限 100），其余轴 *= 0.7，精力 -5（tired 除外）。
→ 这就是"惯性"：旧情绪衰减但不消失，新情绪不会瞬间占满。

**时间衰减（每次调用自动）**：距上次更新每过 1 小时，各轴 -3，精力向 70 靠拢。
→ 不驻留也能模拟"过一会儿就消气了"。

## 为什么要落盘
插件一问一答就退出，情绪必须跨调用保留。存 `%APPDATA%` 下的 JSON，不存插件目录（绿色软件可能只读）。

## 它能做什么 / 不能做什么
- ✅ 情绪状态计算、惯性、衰减、持久化、输出情绪意图
- ❌ 不控制表情贴图（那是宿主的 `intent_payload.expression` 该做的事）
- ❌ 不做自然语言情绪识别（是哪句话触发的由宿主/上层模型判断，本插件只接收情绪名）

## 宿主接入
读 `intent_payload`：
- `type=emotion` → 设置桌宠表情/语气
- `energy < 35` → 播疲惫/打盹动画
- `mood=angry` → 气泡文案可更嘴硬

## 已知边界
- 情绪识别依赖上游把用户话转成情绪名；本插件提供 `TRIGGER` 关键词表兜底，但不是 NLP。
- 六轴是简化规则模型，情绪识别依赖上游输入（用户描述或上层模型判断）；本插件不做 NLP，也不假设任何参考项目内部如何实现。
