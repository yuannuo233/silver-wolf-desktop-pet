# weather · 技术路线

## 与 MCP 原版的差异
原 `tools/weather.py` 用 `requests`。这里改写为 `urllib.request`（标准库），目的是让插件**零 pip 依赖**——桌宠是绿色软件，用户不一定装了 requests。

其余业务逻辑完整复用：
- 20 个常用中文城市坐标表（避免每次查地理编码）
- 非内置城市走 Open-Meteo geocoding API
- WMO 天气代码翻译成中文

## 数据流
```
ask(city) → 内置表命中? ─是→ 坐标
                └否→ geocoding API → 坐标
                          ↓
                 forecast API (current + optional daily)
                          ↓
                 WMO 代码翻译 + 拼中文句子 → text
```

## 超时与降级
- HTTP 超时 12 秒（气泡等待不能太久）。
- 网络不通 / API 报错 → 返回 `ok:true` + `degraded:true` + 友好提示，不让气泡显示技术错误码。
- 城市解析失败 → 返回 `ok:false` + 明确原因（这种是用户输入问题，不是网络问题）。

## 为什么不用和风天气
开发说明里提到"天气模板用的是和风天气（需注册拿 key）"。本项目改用 Open-Meteo，理由：
1. 免注册、免 key，插件丢进去就能用；
2. 你的规则是"能直接用开源内容就别自己写"——MCP 包已经实现了 Open-Meteo 方案，直接复用；
3. 国内直连 Open-Meteo 通常可达，失败也有降级。

## 已知边界
- 内置城市表只有 20 个；冷门城市靠地理编码，多一次 HTTP 往返。
- 预报天数被夹到 1~7（API 限制）。
- 返回的是查询瞬时天气，不是持续更新；要常驻显示需宿主定时调用。
