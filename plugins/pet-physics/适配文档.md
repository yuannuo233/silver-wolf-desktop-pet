# pet-physics 物理反馈 · 适配文档

> 适配目标：银狼桌宠（Silver Wolf Desktop Pet）v0.6.20
> 插件版本：v1.0.0　|　编写日期：2026-11-24
> 对应文件：`plugin.json` / `main.py` / `README.md` / `技术路线.md` / 本文件

## 1. 适配目标与前置条件

按用户口述的"点击 Q 弹回嘴、拖拽甩抛后沿屏幕边缘反弹"等需求做成**物理意图层**。插件只描述该发生什么，真正位移/回弹由宿主引擎实现。

前置条件：

- 宿主要有物理或补间动画能力（v0.6.20 的 `pet.py` 有拖拽 `_on_drag()` 和移动 `_move_step()`，但没有弹性碰撞引擎）。
- 宿主要读 `intent_payload.event` / `intensity` / `restitution`；只读 `text` 的话就只有气泡。

## 2. 本插件的返回字段

hello（实测）：

```json
{"t":"reply","ok":true,"intents":["pet_physics","互动","物理","bounce","弹"],
 "description":"物理反馈意图（Q弹/甩抛/边缘反弹），需宿主物理引擎",
 "events":["click","drag","edge","poke","release","shake","throw"]}
```

ask（实测，`event=poke`）：

```json
{
  "t": "reply", "ok": true, "text": "别戳我！",
  "intent_payload": {"type":"physics","event":"bounce","intensity":0.6},
  "event": "poke", "event_name": "戳一下", "effect": "bounce"
}
```

带 intensity 时，`intent_payload` 会多出 `restitution`（弹性系数，约 0.4~0.9）。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `text` | str | 气泡文字（Q 弹回嘴） |
| `intent_payload.type` | str | 固定 `physics` |
| `intent_payload.event` | str | 宿主实际动作：`bounce` / `fling` / `edge_bounce` 等 |
| `intent_payload.intensity` | float | 强度 0~1 |
| `intent_payload.restitution` | float | 弹性系数（throw/drag 时有） |
| `event` / `effect` | str | 原始输入事件与建议效果，方便调试 |

7 种输入事件：`click` / `drag` / `edge` / `poke` / `release` / `shake` / `throw`。

## 3. 宿主接入点与字段映射

| 插件字段 | 宿主函数（v0.6.20 真实位置） | 处理方式 |
| --- | --- | --- |
| `text` | `pet.py:773 show_bubble(text)` | 直接传入 |
| `intent_payload.event=bounce` | `pet.py:686 _on_press()` / `:717 _on_release()` 后可加回弹补间 | **需宿主新增**，现有代码没有弹性计算 |
| `intent_payload.event=fling` | `pet.py:698 _on_drag()` 记录的位移可当初速度 | **需宿主新增**惯性计算 |
| `intent_payload.event=edge_bounce` | 窗口位置 + 屏幕边界检测 | **需宿主新增**，v0.6.20 无边缘反弹 |

宿主侧接法（伪代码）：

```python
r = plugins_engine.ask("pet-physics", intent, args)
pet.show_bubble(r["text"])
p = r.get("intent_payload", {})
if p.get("type") == "physics":
    if p["event"] == "bounce":
        pet.squash_and_recover(p["intensity"])   # 宿主需实现
    elif p["event"] == "fling":
        pet.apply_velocity(last_drag_delta * p["intensity"])
    elif p["event"] == "edge_bounce":
        pet.bounce_at_edge(p.get("restitution", 0.6))
```

## 4. 状态文件与路径

无状态。每次调用按输入事件即时计算意图参数，不写文件。

## 5. 接入步骤

1. 拷 `plugins/pet-physics/` 到桌宠 `plugins/`，重启启用（id=`pet-physics`）。
2. 宿主的拖拽/点击事件里调本插件，拿到 `intent_payload`。
3. **实现缺失的物理层**：`squash_and_recover` / `apply_velocity` / `bounce_at_edge` 这三个函数在 v0.6.20 源码里不存在，需宿主自行加。
4. 不想做物理也至少有气泡回嘴：`show_bubble(r["text"])` 就能用。
5. 调 `intensity` 可控制效果强弱；`restitution` 越大越"弹"。

## 6. 验证方法

```bash
cd plugins/pet-physics
echo '{"t":"hello"}' | python main.py
echo '{"t":"ask","id":"1","intent":"pet_physics","args":{"event":"poke"}}' | python main.py
echo '{"t":"ask","id":"2","intent":"pet_physics","args":{"event":"throw","intensity":0.9}}' | python main.py
```

预期：hello 列出 7 个事件；throw 高 intensity 时 `restitution` 接近 0.85；stdout 只有一行 JSON。宿主内验证要看是否有实际位移/回弹——没有的话说明宿主还没接 `intent_payload`。

## 7. 边界与降级

- **这是最"意图化"的插件**：不接宿主物理层就完全看不到效果，只有气泡。这是协议边界，不是插件 bug。
- 未知 `event` 返回 `ok:false` + 提示，不崩。
- 插件不操作鼠标、不注入进程、不改窗口属性；一切位移由宿主完成。
- 本机源码没有 `plugins_engine.py`，宿主调用链为协议设计，未在本机实测。
