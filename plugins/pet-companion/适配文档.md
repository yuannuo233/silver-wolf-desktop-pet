# pet-companion 自主行为 · 适配文档

> 适配目标：银狼桌宠（Silver Wolf Desktop Pet）v0.6.20
> 插件版本：v1.0.0　|　编写日期：2026-11-24
> 对应文件：`plugin.json` / `main.py` / `README.md` / `技术路线.md` / 本文件

---

## 1. 适配目标与前置条件

按用户口述的"桌宠自主小动作/碎碎念"需求做成意图层：看鼠标、发呆、歪头、低频小动作轮换，以及偶发的一句话。

前置条件：

- 宿主要有低频定时器（建议 60~180 秒问一次），否则"自主"不会发生——插件不驻留。
- 宿主要读 `intent_payload.action` 才能触发动作；只读 `text` 的话只有碎碎念气泡。
- 宿主已有 `pet.py:619 _watch_activity()` 的活动检测，两者可叠加但要避免抢状态。

## 2. 本插件的返回字段

hello（实测意图）：`["companion","陪伴","碎碎念","自主", ...]`。

ask（实测，行为）：

```json
{"t":"reply","ok":true,"text":"（她盯着窗外发了一会儿呆）",
 "intent_payload":{"type":"companion_action","action":"daydream","name":"发呆"},
 "behavior":"daydream"}
```

ask（碎碎念）：

```json
{"t":"reply","ok":true,"text":"……",
 "intent_payload":{"type":"companion_chatter","line":"……"}}
```

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `text` | str | 气泡文字 |
| `intent_payload.type` | str | `companion_action` 或 `companion_chatter` |
| `intent_payload.action` | str | 建议动作 id（如 `daydream`） |
| `intent_payload.line` | str | 碎碎念文本（等于 text） |
| `behavior` | str | 顶层冗余字段，方便调试 |

支持 `args`：`action`（`behavior` / `chatter` / `reset`）、`id` 等。轮换用 `last_idx` 避免连续重复同一条。

## 3. 宿主接入点与字段映射

| 插件字段 | 宿主函数（v0.6.20 真实位置） | 处理方式 |
| --- | --- | --- |
| `intent_payload.action=daydream` 等 | `pet.py:527 play_action(state)` 或 `:452 set_anim_state(state)` | 有对应帧就播，没有就跳过动作只留气泡 |
| `intent_payload.line` | `pet.py:773 show_bubble(text)` | 直接传入 |
| `text` | 同上 | 行为描述也可进气泡 |

**与宿主活动检测的冲突处理**：`pet.py:641` 有一段"一次性动作播放中，_activity 不接管"的保护（`self._action_live`）。宿主接本插件时，建议把 `companion_action` 也纳入 `_action_live` 保护，否则打字/游戏状态可能把自主动作抢掉。

建议宿主接法（伪代码）：

```python
r = plugins_engine.ask("pet-companion", intent, args)
pet.show_bubble(r["text"])
p = r.get("intent_payload", {})
if p.get("type") == "companion_action" and p["action"] in pet.anim_states:
    pet.play_action(p["action"])   # 一次性，播完回 idle
```

## 4. 状态文件与路径

- 文件：`%APPDATA%\SilverWolfPet\plugins\pet-companion\companion.json`
- 回退路径：`~/.config/SilverWolfPet/plugins/pet-companion/`
- 内容：`last_idx`（上次行为索引）、`last_line`（上次碎碎念索引）、`last_at`（时间戳）
- 作用：避免连续重复；`reset` 可清空。

## 5. 接入步骤

1. 拷 `plugins/pet-companion/` 到桌宠 `plugins/`，重启启用（id=`pet-companion`）。
2. 宿主加低频定时器（60~180 秒）调 `behavior`，偶尔调 `chatter`。
3. 接 `intent_payload.action` 到 `play_action()`；把自主动作纳入 `_action_live` 保护避免被抢。
4. 观察是否"不机械重复"——`last_idx` 轮换保证相邻两次不同。
5. 调 `reset` 清空轮换记录便于测试。

## 6. 验证方法

```bash
cd plugins/pet-companion
echo '{"t":"hello"}' | python main.py
echo '{"t":"ask","id":"1","intent":"companion","args":{"action":"behavior"}}' | python main.py
echo '{"t":"ask","id":"2","intent":"companion","args":{"action":"chatter"}}' | python main.py
```

预期：连续两次 `behavior` 的 `action` 不同；`chatter` 返回句子；状态文件里 `last_idx` 递增。

## 7. 边界与降级

- **插件自己不会定时**；没有宿主定时器就完全不会"自主"。这是协议边界。
- 动作能否发生取决于角色包有没有对应帧；没有就只有气泡。
- `last_idx` 存在本地 JSON，多开桌宠时可能不同步，但不影响单实例使用。
- 本机源码没有 `plugins_engine.py`，宿主调用链为协议设计，未在本机实测。
