# reminder · 技术路线

## 与 MCP 原版的差异
原 `tools/reminder.py` 的 `add_reminder` / `list_reminders` / `check_due_reminders` / `complete_reminder` / `delete_reminder` 全部逻辑复用，做了三处改造：

1. **数据库路径**：从"包内 data/"改到 `%APPDATA%\SilverWolfPet\plugins\reminder\`。原因：插件可能被放在只读目录，且桌宠升级不该清掉用户提醒。
2. **协议适配**：5 个 MCP tool 合并成一个 intent，用 `args.action` 分发（开发说明只有一个 `intent` 字段）。
3. **默认动作**：没写 action 时按"列出"处理，最安全（不会误删、误加）。

## 为什么用 SQLite 而不是 JSON
- 提醒有"到期时间升序""按 id 改状态"这类查询，SQLite 一行 SQL 搞定，JSON 要自己排序遍历。
- 并发安全：桌宠可能同时问多个问题，SQLite 自带锁。
- 标准库自带，零依赖。

## 到期判断为什么不用字符串比较
不同提醒的 ISO 时间可能带不同时区偏移（+08:00 / Z），字符串比较会错。原版已经踩过这个坑，这里沿用修复后的做法：`datetime.fromisoformat()` 转成带时区对象再比。

## 去重机制
`check` 默认把查到的到期提醒标记 `fired=1`，这样宿主重复调用不会反复提醒同一条。`done` 是用户主动完成，`fired` 是系统已提醒，两者独立。

## 已知边界
- 插件本身不后台定时检查——它是一问一答的。要"到点自动弹气泡"，需要宿主定时发 `check` 意图。
- 提醒时间用本机时区解释没写时区的输入。
