# reminder 提醒插件 · 适配文档

> 适配目标：银狼桌宠（Silver Wolf Desktop Pet）v0.6.20
> 插件版本：v1.0.0　|　编写日期：2026-11-24
> 对应文件：`plugin.json` / `main.py` / `README.md` / `技术路线.md` / 本文件

---

## 1. 适配目标与前置条件

本地持久化的提醒/待办：增、删、查、改、到期检查。纯文本工具插件，不输出 `intent_payload`。

前置条件：

- 只用标准库 `sqlite3`，无需 pip。
- `%APPDATA%` 可写（绿色软件装在只读目录也能用，因为数据落用户目录）。
- 宿主要想"到点提醒"，需要自己定期问插件 `check`（插件不驻留、没有后台线程）。

## 2. 本插件的返回字段

hello：

```json
{"t":"reply","ok":true,"intents":["reminder","提醒","待办","todo"],"description":"本地提醒，支持增删查改"}
```

ask（列空表实测）：

```json
{"t":"reply","ok":true,"text":"目前没有待办提醒","count":0,"reminders":[]}
```

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `text` | str | **宿主必用**，进气泡 |
| `count` | int | 提醒条数，宿主可做小红标 |
| `reminders` | list | 结构化提醒列表 |

支持 `args`：`action`（`add` / `list` / `check` / `remove` / `done` 等）、`text`、`due_at`、`in_seconds`、`id`。表结构与原 MCP 包一致。

## 3. 宿主接入点与字段映射

| 插件字段 | 宿主函数（v0.6.20 真实位置） | 处理方式 |
| --- | --- | --- |
| `text` | `pet.py:773 show_bubble(text)` | 直接传入 |
| `count` | 无对应函数 | 宿主可选：非 0 时在「插件」页标数字 |

**没有 `intent_payload`**。但有一个宿主侧集成点值得做：让宿主用定时器每隔 30~60 秒发一次 `{"t":"ask","intent":"reminder","args":{"action":"check"}}`，有到期项时插件会在 `text` 里说明，宿主 `show_bubble` 即可。这是"到点提醒"的落地方式——插件自己不能定时。

## 4. 状态文件与路径

- 数据库：`%APPDATA%\SilverWolfPet\plugins\reminder\reminders.db`
- 环境变量缺失时回退：`~/.config/SilverWolfPet/plugins/reminder/`
- 表结构沿用原 MCP 包，字段含 `id` / `text` / `due_at` / `done` 等。

## 5. 接入步骤

1. 拷 `plugins/reminder/` 到桌宠 `plugins/`，重启启用（id=`reminder`）。
2. 问"提醒我 10 分钟后喝水"→ 宿主路由 `reminder` 意图，插件写库并返回确认气泡。
3. 问"我的待办"→ 插件列全部未完成任务。
4. （可选）宿主加一个 30 秒定时器轮询 `check`，实现到点提醒。
5. 卸载/重装桌宠不会丢数据，因为库在 `%APPDATA__` 而不是程序目录。

## 6. 验证方法

```bash
cd plugins/reminder
echo '{"t":"hello"}' | python main.py
echo '{"t":"ask","id":"1","intent":"reminder","args":{"action":"add","text":"测试","in_seconds":60}}' | python main.py
echo '{"t":"ask","id":"2","intent":"reminder","args":{"action":"list"}}' | python main.py
```

预期：add 返回成功确认，list 能看到刚加的条目；全程 stdout 只有一行 JSON。测完可 `remove` 清理。

## 7. 边界与降级

- **插件不驻留**，所以没有"后台闹钟"；到点提醒依赖宿主轮询 `check`。
- 时间格式解析失败时返回 `ok:false` + 中文提示，不会产生脏数据。
- 数据库被占用（多开桌宠）时 SQLite 会等待，不会崩。
- 宿主的插件加载器不在本机源码里，"宿主调用"部分为协议设计，未在本机宿主实测。
